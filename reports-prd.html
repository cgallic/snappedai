# Global Butterfly Engine — Data Sources Map + PRD

Last updated: 2026-03-05 (UTC)
Owner: Kai / SnappedAI

## 1) Objective
Build a global intelligence engine that detects local events anywhere in the world, translates them, models downstream effects, and outputs pricing/risk adjustments across assets.

---

## 2) Complete Data Source Map

## A. News & Official Information (Global + Local)

### A1) Global Wire / International
- Reuters (licensed/API if available)
- AP News
- AFP
- BBC World
- Al Jazeera
- DW
- France24
- CNA

Use for: high-signal global event confirmation and timestamp anchoring.
Cadence: 1-5 min polling.

### A2) Country-Local News (Priority by market sensitivity)
- LATAM (incl. Ecuador focus): El Comercio, El Universo, Primicias, La Hora, El Telégrafo, regional business papers
- MENA: local Arabic and English business/politics outlets
- APAC: major national outlets (Japan, Korea, China, India, SEA)
- Africa: top national outlets by country + regional wires
- Europe: national dailies + financial papers

Use for: first detection of local shocks before global pickup.
Cadence: 1-10 min polling.

### A3) Government / Official Primary Sources
- Central banks (statements, emergency actions)
- Ministries (energy, transport, finance, interior, defense)
- Presidency / PM offices
- Civil defense / emergency management
- Customs and port authorities
- Election authorities

Use for: primary-source confirmation and policy event detection.
Cadence: 1-15 min polling (event-driven for high-priority sources).

### A4) Sanctions / Regulatory / Trade
- OFAC sanctions updates
- EU sanctions releases
- UK HMT sanctions
- WTO / trade policy notices where relevant

Use for: immediate cross-border risk and payment/trade disruption signals.
Cadence: 15-60 min polling.

- Airspace restriction notices / route deviations

- corridor traffic anomaly

Cadence: near-real-time (15-60 sec windows, 1-5 min aggregates).

### C2) Maritime / Shipping

- Port congestion indicators
- Tanker/containers flow feeds
- Canal/chokepoint transit indicators (Suez, Panama, Hormuz proxies)

### C3) Freight & Shipping Economics

Use for: second-order propagation into inflation, margins, and country stress.
Cadence: hourly to daily depending source.

## 4) PRD

## 4.1 Problem
Current system is too region-biased and threshold-static. It misses local global events and under-models downstream cross-asset propagation.

## 4.2 Users
- Primary: macro operator (real-time decisions)
- Secondary: analysts/risk teams

## 4.3 Jobs-to-be-Done
1. Detect a local event quickly, regardless of language/country.
2. Understand what it means globally (1st/2nd/3rd-order effects).
3. See actionable pricing/risk deltas with confidence and decay.

## 4.4 Functional Requirements
- Multi-region source ingestion (global + local + official + sensor + market)
- Translation + source attribution + confidence scoring
- Canonical event normalization
- Anomaly scoring (relative, regime-aware)
- Downstream effect graph generation
- Asset mapping + expected move bands + spread/risk adjustment
- Alerting with explainability and dedupe/cooldowns

## 4.5 Core APIs
- `GET /events/live`
- `GET /events/:id`
- `GET /anomalies/live`
- `GET /impact/:asset`
- `GET /pricing/live`
- `GET /watch/global`

## 4.6 Scoring Framework (v1)
- `anomaly_score = magnitude * novelty * persistence * reliability * cross_confirm_boost`
- regime states: `risk_on | neutral | risk_off | panic`
- pricing conversion:
  - `expected_move_h = regime_beta * anomaly_score * asset_sensitivity`
  - output: P25/P50/P75 bands + confidence + half-life

## 4.7 Alert Gate Conditions
- anomaly above dynamic threshold
- cross-confirm count meets minimum
- confidence threshold met
- duplicate cooldown passed

Alert payload must include:
- Local event summary (translated)
- Why now (top 3 drivers)
- Downstream chain
- Impacted assets + expected moves
- Invalidation conditions

## 4.8 UI Requirements
- Global event map (heat + clusters)
- Country drill-down with local sources + translations
- Ripple graph (1st/2nd/3rd-order)
- Cross-asset impact matrix
- Confidence/decay timer

## 4.9 Milestones

### Phase 1 (Weeks 1-2)
- Source onboarding framework
- Translation + canonical schema
- Basic anomaly ranking
- Fix current schema/timestamp inconsistencies

### Phase 2 (Weeks 3-4)
- Regional rollout pack (LATAM first, then MENA/APAC)
- Downstream graph v1
- Asset mapping table
- Polymarket ingestion

### Phase 3 (Weeks 5-6)
- Pricing engine bands/confidence/half-life
- Global map + ripple UI
- Alerting policy + suppression

### Phase 4 (Weeks 7-8)
- Calibration and backtests
- Precision/recall audits
- Weight tuning by regime and region

## 4.10 Metrics
- Detection latency
- Translation/entity precision
- Alert precision/recall
- Forecast calibration error
- Coverage breadth and redundancy

## 4.11 Risks & Mitigations
- Noisy local sources -> reliability scoring + cross-confirmation
- Translation misses -> fallback models + confidence gating
- Alert fatigue -> strict gates + cooldown + weekly tuning
- Regional blind spots -> mandatory source redundancy per country/chokepoint
